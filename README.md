# 新海美學牙醫診所・助理排班系統

單一 HTML 檔的排班系統（`index.html`），不用建置，也不需要安裝套件。原本是 Claude Artifact，放在這裡方便繼續開發。

## 目前能做什麼

| 分頁 | 功能 |
|---|---|
| 排班表 | 以月為單位、按週顯示早／午／晚三班 × 5 個崗位。可拖曳或點選排班，也可以放「缺口」；把人拖到同職務的另一個人上會互換位置（跟診配對留在原位置，基本／加診身分跟著人走；原始班表不能換進有請假的診次） |
| 醫師休假 | 登記醫師休假（依日期與班別），自動排班時會避開 |
| 助理請假 | 登記各類假別；另有「家庭照顧假」（以小時計，未滿 1 小時以 1 小時計；上班到中途請到當診結束時勾選「且到當診結束」；須填寫事由，結束時間固定為當診結束時間，以 0.5 小時為單位、未滿 0.5 小時以 0.5 小時計，紀錄帶 `mid: true`；不影響排班） |
| 診所休診 | 休診日（全天休診的日期），班表不排班 |
| 工時統計 | 助理的班數、全天班、早+晚、各崗位班數、基本工時（只算基本診次，不含加診）、合理工時、超時；可自訂統計區間 |
| 人員名單 | 管理人員／醫師／助理，可設為離職（醫師、助理各有「查看已離職人員」按鈕）、記錄個資、設定權限 |
| 排班規則 | 預設醫師班表、不參與自動排班的助理（含「教育中」：不參與任何職位的自動排班，存在 `cfg.training`）、每崗位人數、上限設定、營業時段 |

上方工具列：切換月份、**回復上一動作**（Ctrl+Z，最多 50 步，只記本次開啟後的排班變更；定案或刪除人員後清空）、**帶入醫師班表**、**自動排班**（可復原）、**匯出班表**：JPG 或 PDF（A4 橫式，整個月放在同一頁，整體等比例縮小），或 Excel（班表、工時統計、請假、薪資等工作表）。

## 程式結構（都在 `index.html` 的 `<script>` 內）

```
CSS（:root 色彩變數，支援深色模式）
HTML（7 個 <section id="tab-*">）
<script>
  常數     SHIFTS（三班，每班 3.5h）、POS（主櫃/副櫃/跟診/流動/健保）、DEFAULT_CFG
  狀態     staff, cfg, weeks, leaves, familyCare, privateInfo, accessLinks
  日期     monthInfo(), mondayOf(), ymd()
  存取     store.*（先更新記憶體 → renderAll() → 寫入 DB 或 localStorage）
  啟動     boot()：有 FIREBASE_CONFIG 就走 Google 登入 + Firestore，否則改用 localStorage
  薪資     payCfg(), calcPay(), renderPay(), openAdj()
  畫面     renderAll() → renderWeeks / renderLeave / renderStats / renderSettings / renderRules / renderHolidays
  排班     autoSchedule(fillOnly), undoAuto()
  匯出     exportBtn → SheetJS (xlsx 0.18.5, CDN)
</script>
```

### 資料模型

- **staff**：`{id, role: 'manager'|'doctor'|'assistant', code, name, active}`
- **weeks[週一日期 'YYYY-MM-DD']**：
  - `"{dow}_{shift}"`（例如 `"0_day"` = 週一早班）→ 長度 5 的陣列，對應 POS 的 5 個崗位，每格是人員 id 陣列（`'_gap'` 表示缺口）
  - `"L{dow}_{shift}"` → `[[助理id, 醫師id], ...]` 跟診配對
  - `"T{dow}_{shift}"` → `[[學員id, 教育者id], ...]` 教育配對：「教育中」的助理只能排在其他助理下方（拖到或點選後點到負責教育的助理身上），顯示為藍色虛線框；教育者被移除時學員一併移除，教育者有學員時不能移到別格
- **leaves**：`{id, staffId, date, shifts: ['day','eve','night'], type, note}`
  - **請假審核**：助理、醫師自己登記（權限是「本人」，沒有排班管理以上）的請假／休假要審核。新增、修改、取消都存成同一個集合裡的申請：`status:'pending'`、`kind:'add'|'edit'|'cancel'`、`replaces`（修改／取消的原本那筆）、`reqAt`。程式讀取時把有 `status` 的分到 `leaveReqs`，`leaves` 只放已核准的，所以排班、薪資、統計只看已核准的請假。
  - 「助理請假」與「醫師休假」分頁最上方：管理者看到「請假審核」／「休假審核」（核准、退回可填原因、全部核准）；本人看到「我的請假申請」／「我的休假申請」（待審可撤回、被退回的可刪除）。分頁列顯示待審筆數。整月排假／整月排休裡待審的申請以虛線框顯示（取消申請加刪除線），點一下撤回。
  - 批量處理（`reqSiblings()`／`askBatch()`）：同一件事（`pevId`／`eventId` 相同），或沒有事件但同一次送出（同假別、送出時間相差 5 秒內）的待審申請算同一批，新增／修改一組、取消申請一組。管理者核准、本人在「我的請假申請」撤回、在請假列表撤回刪除／變更申請時，有同一批的其他申請就詢問「全部（N 筆）」或「只這一筆」。
  - 核准：新增／修改換掉當天原本的請假（申請內容已含原本班次），記錄 `approvedBy, approvedByName, approvedAt`；取消則刪除原本那筆。退回：`status:'rejected', reason, reviewerName, reviewedAt`。
  - 規則：助理、醫師本人只能建立 `status:'pending'` 的請假／休假、只能刪除待審或被退回的；已核准的只有排班管理以上能改。
  - **證明文件提示**：`LEAVE_PROOF` 列出婚假、喪假、病假、產假、產檢假、陪產假（陪產檢假）、流產產假、育嬰假、彈性育嬰假、家庭照顧假、公假常見需檢附的證明文件與說明。請假表單、整月排假選到這些假別時顯示提示；審核表格在假別下方列出需檢附的文件；「助理請假」分頁有「假別與證明文件」對照表（點開查看）。只適用助理，醫師休假不需檢附證明。
  - **請假登記表篩選**：請假登記（事前／事後）與醫師休假列表的「日期、人員、班別、類別、狀態」表頭除了排序，下方也有下拉選單可組合篩選（整年檢視時日期改選月份；狀態分無衝突、已排班、等待核准變更、等待核准刪除），篩選時最右欄顯示「清除篩選」與「N／M 筆」（`lvFilters`）。
  - **家庭照顧假篩選**：家庭照顧假列表的「日期、助理、班別、時間段」表頭下方也有下拉選單可組合篩選（整年檢視時日期改選月份），篩選時最右欄顯示「清除篩選」與「N／M 筆」（`fcFilter`）。
  - **審核表篩選**：請假審核／休假審核表頭的「日期（年月）、人員、申請、班別、假別」都是下拉選單，可以組合篩選，選中的欄位會反白；篩選時標題顯示「待審 N／M 筆」，「全部核准」改成「核准篩選的 N 筆」，表頭最右邊有「清除篩選」（`reqFilter`、`reqPass()`）。
  - **缺證明提醒**：「助理請假」分頁最上方列出尚未附證明的請假（同一件事或同一段連續日期合成一筆，含審核中與家庭照顧假；助理只看自己的，管理者看全部；只算保存期限內的），點一下直接開啟證明視窗；分頁列顯示「助理請假（待審數・缺證明 N）」（`missingProofs()`）。
  - **上傳證明**：請假列表、家庭照顧假列表、審核／我的申請表格的假別旁顯示「⚠ 未附證明」「📎 n 份證明」「📄 已收紙本」，點一下開啟證明視窗：上傳照片或 PDF（照片自動壓縮成 JPEG、最長邊 1600px、小於約 900KB；PDF 需小於 700KB），可勾選「同一次請假（同人同假別的連續日期）都套用」；喪假、婚假、產檢假、產假、流產產假的證明綁定所屬事件（`leaveProofs.pevId`，舊證明依上傳日期推算），同一件事（例如同一人過世）之後再請的假自動套用同一份證明；育嬰假與彈性育嬰假以子女生日為群組，同一名子女的兩種假共用證明；管理者可勾選「已收到紙本證明」。送出需要證明的假別（含家庭照顧假）後會直接詢問「要現在上傳證明嗎？」（上傳證明／稍後再說）；整月排假裡同一段連續假只詢問一次、已有證明就不問。資料：清單 `leaveProofs/{id}`（`staffId, dates[], type, kind:'file'|'paper', name, mime, size, by, byName, at`），檔案內容 `proofFiles/{id}`（`staffId, data` dataURL，點開時才讀取）。只有本人與排班管理以上看得到；本人只能上傳、刪除自己的檔案，紙本標記只有管理者能做。保存期限 `config/main.proofKeepMonths`（預設 24 個月、0＝永久，在「假別與證明文件」卡片設定），以請假最後一天起算，管理者開啟系統時自動刪除過期證明。
- **familyCare**：`{id, staffId, date, shift, start, end, hours, note}`
- **cfg**：`need[5]`（每崗位人數）、`maxPerDay`、`otMax`、`maxFullDays`、`maxDN`、`nhOnly`、`closed{"dow_shift":true}`、`holidays{date:{name}}`、預設醫師班表、排除名單
- **privateInfo / accessLinks**：人員個資、帳號與權限（view / self / manage / super）

### 自動排班演算法（`autoSchedule`）

依階段填入，人手不足時缺口會留在後面的階段：

1. **主櫃**與**跟診醫師**
2. **跟診配對**：幫醫師配助理，同一醫師同一天盡量由同一位助理跟
3. **健保**（可以限定只排某些助理）
4. **流動**（依晚 → 午 → 早的順序）
5. **副櫃**（依午 → 晚 → 早的順序）

排完後的調整（跟診、主櫃連貫互換）不會讓前面階段的崗位變空：最後一步「跟診盡量由同一人」只有在能把原本的跟診助理換回主櫃時，才會從主櫃調人（主櫃優先於跟診）。

**缺口診斷**：班表上紅色虛線的缺口（助理崗位）點一下，會列出每位助理目前能不能排進來，以及不能的原因（請假、已在這一診、當天班數上限、工時上限、全天班或早＋晚次數上限、排除名單、教育中）。

候選人的硬性條件：沒有請假、沒被排除、當天班數 < `maxPerDay`、全天班／早+晚次數沒超過上限，且工時不超過「合理工時 + 超時上限」。

排序分數（越低越優先）＝ 本月班數 + 全天班／早+晚平均分配懲罰（×10000）+ 超過合理工時懲罰（1e6 起跳）。分數相同時，用 hash 讓結果固定。

工時統計標題旁可用「◀ 月｜年 ▶」把統計期間切換成其他整月或整年（也可自訂起訖日期）。

**合理工時** ＝ 可排班天數 × 8；可排班天數 ＝ 期間天數 − 週日 − 診所休診日 − 非營業日 − 事前請假的日子（事後請假不影響）

## 線上部署（GitHub Pages + Firebase）

- **網站**：GitHub Pages 直接提供 `index.html`，推上 `main` 就會更新。
- **登入**：Firebase Authentication（Google 帳號）。
- **資料**：Cloud Firestore，所有人即時同步。
- **權限**：由 [`firestore.rules`](firestore.rules) 在伺服器端檢查，前端的按鈕停用只是介面提示。

`index.html` 開頭的 `window.FIREBASE_CONFIG` 設為 `null` 時，會退回本機 localStorage 模式，方便離線開發。

### 權限

| 等級 | 可以做什麼 |
|---|---|
| 僅檢視 `view` | 助理只看得到 5 個分頁：排班表、出勤（只有自己的出勤統計、出勤明細、加班申請、打卡紀錄）、助理請假（只有自己的申請、請假、家庭照顧假與假別統計）、薪資（只有自己的）、排休抽籤；醫師：排班表、自己的休假、待自己審核的加班；未綁定人員：只有排班表。僅檢視不能登記請假 |
| 登記本人請假 `self` | 看得到的分頁與僅檢視相同（`lowPerm()`／`viewTabs()`），另外可以登記／變更自己的請假與家庭照顧假（需管理者審核；表單不顯示選擇人員的欄位，整月排假自動選好自己）、上傳證明、參加排休抽籤 |
| 排班管理 `manage` | 排班、所有人的請假、休診日、規則、出勤；薪資只看自己的（助理） |
| 超級管理員 `super` | 上述 + 所有人的薪資（含薪資計算規則、帶入薪資）+ 個資 + 設定權限 |

- `OWNER_EMAILS`（`index.html`）與 `firestore.rules` 裡列出的 Gmail 不必綁定，一律是超級管理員；兩邊要一致。
- 其他人要由超級管理員到「人員名單 → 權限」填入 Gmail 並選擇權限，才能登入。新設定時預設為「僅檢視」。
- 「停權」（人員名單，離職左邊）：超級管理員可以暫停某人的登入，保留帳號綁定，`access/{Gmail}.perm` 改為 `suspended`、原本的權限存在 `prevPerm`；被停權的人登入後只會看到停權訊息，Firestore 規則也不給任何讀寫權限。按「恢復權限」還原。

### 多人同時編輯班表

- **即時同步**：班表以 Firestore 即時同步，別人的修改約一秒內出現。
- **誰在編輯**：排班管理以上的人開著排班表分頁時寫入 `presence/{自己的 uid}`；班表上方顯示「XXX 也在編輯 2026年 10月班表」（看其他月份的人另外列出）。
- **只寫有變動的診次**：`store.cells` 以交易讀取最新內容再寫入；崗位格（`0_day` 這類，5 個崗位）只覆蓋自己有變動的崗位，其他崗位保留別人的修改。`store.week`（整週替換）也改成只寫出不同的診次。
- **回復（Ctrl+Z）**：每一步記下自己改過的診次改前／改後；回復時只還原仍是自己改後樣子的診次與崗位，別人之後改過的保留不動。
- **整週覆蓋前確認**：清空本週、清空本月、一鍵帶入／帶入醫師班表、自動排班、復原，若這幾週 10 分鐘內被其他人改過，先跳出「這幾週剛被其他人修改過」確認。

### Firestore 資料結構

| 路徑 | 內容 |
|---|---|
| `weeks/{週一日期}` | `c.{dow}_{shift}` 等欄位，值是 JSON 字串（因為 Firestore 不接受巢狀陣列）；`by, name, at` 為最後修改者與時間 |
| `leaveProofs/{id}`、`proofFiles/{id}` | 請假證明清單與檔案內容（見「請假審核」） |
| `presence/{uid}` | 正在編輯班表的人 `{name, email, ym, view, at}`，每 10 秒更新、超過 70 秒視為離開 |
| `baselines/{YYYY-MM}` | 原始班表（定案時的當月班表） |
| `staff/{id}`、`leaves/{id}`、`familyCare/{id}`、`config/main` | 同上方資料模型 |
| `pay/{staffId}_{YYYY-MM}` | `{staffId, ym, base, attend, perf, skill, duty, otMin, selfInd, selfTeam, stars, labor, health, dependents, lateMin, items, note}` 當月薪資項目 |
| `personalEvents/{id}` | 個人事件假（婚假、喪假、產檢假、產假、流產產假、育嬰假）的事件日期 |
| `lottery/{YYYY-MM}`、`lotteryBets/{id}` | 排休抽籤的設定、結果與每人放的籌碼（見「排休抽籤」） |
| `data/private/people/{staffId}` | 個資 |
| `access/{Gmail}` | `{staffId, perm}` 帳號綁定與權限 |

### 薪資

每人每月一筆，還沒儲存的月份顯示為「試算」：
- 本俸、勞保費、健保費、眷屬人數：帶入前一個有紀錄的月份
- 出勤津貼、績效獎金、技能津貼：用預設值
- 其他欄位：0

| 應發 | 算法 |
|---|---|
| 本俸 | 每人每月填寫 |
| 出勤津貼 / 績效獎金 / 技能津貼 | 預設 1000 / 1000 / 3500 |
| 職務津貼 | 每人每月填寫，帶入前一個月的金額（沒有職務填 0） |
| 加診薪資 | 加診數 × 3.5 小時 × 60 × 加班每分鐘 4 元（每診 840 元） |
| All班加給 | 同一天上滿三班（含加診）的天數 × 30 分鐘 × 加班每分鐘 4 元（每天 120 元） |
| 加班薪資 | 加班/拖診分鐘數 × 加班每分鐘 4 元 |
| 國定假日上班加給 | 國定假日上班的診數 × 每診設定薪資 × 1（每診加 595 元；倍數可在薪資計算規則調整），自動寫在備註。國定假日：開國紀念日、除夕前一日～初三（5 日）、和平紀念日、兒童節（與清明同日時依規定前後移）、清明節、勞動節、端午節、教師節、中秋節、國慶日、臺灣光復暨金門古寧頭大捷紀念日、行憲紀念日（`nationalHolidays`）。逢週末的補假不計 |
| 自費獎金 | 個人、團體各一欄 |
| 五星好評 | 則數 × 每則 30 元 |
| 禮金／獎金 | 生日當月加發生日禮金 1000 元；春節、端午、中秋所在月份各加發三節獎金 1000 元（金額可在薪資計算規則調整）。自動寫在備註欄。生日月份由個資的生日同步到 `staff.birthMonth`（只存月份）；三節日期在程式內建 2024–2035 年的對照表 `FESTIVALS`，之後的年份需要補上 |

| 扣除 | 算法 |
|---|---|
| 勞保費 | 每人每月填寫 |
| 健保費 | 本人健保費 ×（1 ＋ 眷屬人數） |
| 遲到 | 遲到分鐘數 × 遲到每分鐘 4 元 |
| 早退 | 早退分鐘數 × 早退每分鐘 4 元（與遲到分開計算；早退超過 30 分鐘也不發出勤津貼，可調整） |
| 請假扣款 | 請假診數 × 每診設定薪資（預設 595，可調整）× 假別扣薪比例。一個班算 1 診。預設比例：事假、不可上班、其他 1，病假、生理假 0.5，其餘 0 |
| 家庭照顧假 | 登記時數 × 每小時 170 元 |
| 育嬰假（月制） | 整個月都在育嬰假：不發任何薪資（含津貼、獎金、禮金），不扣勞健保；只有部分天數：育嬰假期間的上班日每天 2 診 × 每診設定薪資扣除，津貼照發、勞健保照扣 |
| 彈性育嬰假 | 事前登記每天算 2 診、事後補登依請假診數，× 每診設定薪資扣除；不影響出勤津貼 |

加減項（`items:[{label, amount}]`）只屬於當月，不帶入下個月。薪資備註（`note`）同樣只屬於當月，可在「編輯」或「集體編輯」填寫，員工本人在薪資頁也看得到。

薪資表「編輯」欄最上方的「集體編輯」可以在一個表格裡同時填所有助理當月的薪資項目（不含加減項），即時顯示實發，儲存時只寫入有改動的人。

**不發出勤津貼**的條件（任一成立）：當月遲到總分鐘數超過 30 分鐘（可調整）；當月加診診數少於事假診數。

**原始班表／異動班表**：排班表上方切換。定案前在「原始班表」排班（編輯 `weeks`），異動班表尚未產生；按「定案」把當月班表存成原始班表（`baselines/{YYYY-MM}`：`{ym, at, by, weeks:{週一日期: 編碼後的格子}}`，鎖定只能看），之後在「異動班表」繼續修改 `weeks`。重新定案會用目前的異動班表覆蓋原始班表。工時統計與薪資一律依 `weeks` 計算。原始班表不能把人排進他已請假的診次；異動班表可以，且不標示請假，只有助理「事後」補登的請假會以紅色斜線劃掉該診。醫師的休假在原始班表與異動班表都以紅色斜線劃掉該診（原始班表上助理的請假衝突仍標紅色）。

**請假登記（事前／事後）**：助理請假卡片以「事前／事後」按鈕切換（`prefs.lvWhen`），兩邊各有表單、列表與整月排假，紀錄帶 `when: 'before'|'after'`（舊資料視為事前）。兩者功能相同、日期不限制；事後列表同時以淺灰色列出事前紀錄供對照（不可在此修改）。列表標題旁可切換「月／年」並用 ◀ ▶ 查看其他月份或年份；家庭照顧假、醫師休假列表也有同樣的按鈕，各自切換（`rangeViews`，上方月份改變時回到跟著上方月份）。

**家庭照顧假與請假不得同時段**：家庭照顧假的時間段與各班看診時間（早 08:30–12:00、午 13:50–17:20、晚 18:00–21:30）重疊的班次，不能同時有請假；登記或變更任一方時都會檢查（`fcVsLeave`、`leaveVsFc`）。

**年度假別上限**（日曆年；事前請假一天算一天，事後補登兩診算一天）：事假 14 天（家庭照顧假 3.5 小時算一診，與事假合計）、病假 30 天、生理假 3 天。生理假超過 6 診的部分視同病假：計入病假天數，薪資套用病假的扣薪比例與出勤津貼扣法。登記超過上限時，管理者會看到確認視窗、一般助理無法登記。「助理請假」分頁有年度統計表，標題旁可用 ◀ ▶ 切換年份。

**個人假統計**（助理請假分頁）：
- 特休：依到職日（`staff.hireDate`）週年制計算（可用 ◀ ▶ 切換查看其他期，並列出該期的特休日期）——滿 6 個月 3 日、1 年 7 日、2 年 10 日、3–4 年 14 日、5–9 年 15 日、10 年起每年加 1 日至 30 日。以小時計：額度＝天數 × 8 小時；請整天扣 7 小時，事後補登單診扣 3.5 小時。助理**事前**登記的請假一律以日為單位（`isWholeDay`，`store` 寫入時改成全天）；**事後**補登不論假別都以診為單位。
- **個人假統計只算已核准的請假**：年度累計、特休與事件假統計都只看已核准的請假；事件底下還沒有核准的請假時不列入事件假統計。 事件假統計沒有「刪除」按鈕，完全依已核准的請假紀錄同步：請假全部取消後，這件事就不再列出。
- **彈性育嬰假**：以日為單位，每名子女合計 30 日（算在育嬰假 2 年內），可於 1 日前提出（當天或之前的日子助理本人無法送出）。事件以子女生日辨別（`PEV.彈性育嬰假`，`date`＝子女生日），請假時若已登錄過未滿 3 歲的子女（育嬰假或彈性育嬰假填過的子女生日），先詢問「是哪一名子女」，選了就沿用（或自動建立）該子女的彈性育嬰假事件，選「其他子女」才填生日；`childLeaveUsed()` 合計月制育嬰假期間與彈性育嬰假（已核准＋待審核）。薪資扣款預設與育嬰假相同（不扣）。
- **事假、補休、不可上班、其他須說明理由**（助理）：請假表單、整月排假的起訖日視窗、請假列表的「變更」都要在備註／理由填寫，空白時無法送出（`REASON_TYPES`）。
- **假別改名**：「陪產假」更名為「陪產假（陪產檢假）」；舊資料讀取時自動換成新名稱（`normType()`、`RENAMED`）。
- **事件歸屬與空事件**：請假記錄所屬事件（`pevId`，連續假用 `eventId`），判斷時只認所屬的那一件（`evBelongs()`），沒有記錄的舊資料才依期間判斷；選項、婚假 3 個月提醒、產假預設起始日、已登錄的子女都只看底下還有請假的事件。底下沒有任何請假、建立超過 1 天的空事件，管理者開啟系統時自動刪除（`pevCleanup()`）。
- **已過去的請假**：已核准、日期在今天以前的請假，助理本人不能申請取消或變更（store 層與列表都會擋，`pastLeave()`）；連續假的取消只能從今天以後的日子開始。管理者不受限制。
- **連續假**：系統自動排入的產假、流產產假、育嬰假（`eventId`）必須連續，請假列表的「變更」會被擋下；按「刪除」或在整月排假點掉某一天，會開啟「從這一天起取消到最後」（育嬰假以月）的視窗（`cancelCont()`），保留前面連續的部分。待審的連續假申請（新增或取消）在撤回、退回時只能整段一起處理；管理者核准時可以選「全部核准」或「只核准這一筆」。產假、流產產假的撤回與取消只能「從某一天起到最後一天」（`tailDialog()`），保留前面連續的部分；月制育嬰假的撤回與取消以「月」為單位（`ccMonthsDialog()`）：只能從最後面往前減，剩下 0 個月或至少 6 個月；取消核准後依剩下的請假更新事件的結束日（育嬰假一併更新月數，`ccFixEnd()`）。
- **產假、流產產假的接續**：請的日期落在同一件產假／流產產假的可請範圍內（起始日起 56／28／7／5 天）時，先詢問「是不是同一件事」；選同一件就開啟「接續」視窗，開始日固定為上一段最後一天的隔天（必須連續），只選結束日，不超過剩餘天數（產假也不超過生產日後第 55 天），並更新事件的結束日（`contExtend()`）。
- **一次問完**（`ONE_WIN`：病假、公假、婚假、喪假、產檢假、陪產假（陪產檢假）、彈性育嬰假）：事由、結婚登記日、死亡日與親屬關係、預產期等問題和開始／結束日期放在同一個視窗，即時顯示天數（週日、休診日不計），婚假、喪假、產檢假、彈性育嬰假另外顯示可請天數、已請天數（含審核中）與是否超過（彈性育嬰假同時受每名子女 30 天與育嬰假合計 2 年限制）；育嬰假選起始日與月數時即時顯示「請到 ○ 年 ○ 月 ○ 日」、天數與這名子女的 2 年合計；「是不是同一件事」的視窗也一起問起訖日。整月排假點這些假別時不再另外先問起訖日。
- **整月排假的起訖日**：助理整月排假時選病假、事假、公假、婚假、喪假、產檢假、陪產假（陪產檢假）、彈性育嬰假、補休、不可上班、其他，點日期或班次後會先詢問開始與結束日期（預設為點的那天）與備註，再交給請假表單走完整流程（事件、上限、證明），週日與休診日自動略過；月曆在資料變動後自動更新（`monthLeavePaint`）。
- **需要證明的假：標準流程**（助理）
  1. 送出時先詢問事由、日期等相關資料；期限內已有同假種的事件，先問「是不是同一件事」。
  2. 選同一件事：這次的請假記在那件事（`pevId`），自動套用同一份證明。
  3. 選「新的事件」：當作新事件，再詢問事由、日期等資料。
  - 事件底下的請假全部被撤回或刪除（請假列表與待審核都沒有了）時，這件事不再列為選項，新請的假視為新事件。
  - 各假別的期限：婚假＝結婚登記日前 10 日起 1 年內（超過 3 個月需經公司同意）；喪假＝死亡日起 100 日內；產檢假＝預產期前；產假＝連續 56 日（須填預產期〔生產日期〕；生產當天算第 1 天，起始日預設為生產日〔自動帶入時不早於今天〕，起始日不得早於預產期前 28 天，最後一天最晚為生產日後第 55 天；有產檢假的預產期時預先帶入；起訖日旁即時顯示共幾天、最多幾天，超過時標紅）；流產產假＝流產日起 56／28／7／5 日（妊娠 20 週以上／3 個月以上未滿 20 週／2–3 個月／未滿 2 個月）；陪產假（陪產檢假）＝懷孕期間（預產期前 280 天起，可陪產檢）到預產期（生產日期）後 15 日內請完、最多 7 天（週日、休診日不計），第一次請時預產期與起訖日在同一個視窗填寫並即時顯示天數（整月排假也不會再另外問一次起訖日），可分次請；病假、公假每次都是新事件（病假填事由，公假選事由並可補充說明），這次請的幾天共用同一份證明。家庭照顧假不套用。
- 事件假（`personalEvents/{id}`：`{staffId, kind, date, rel, months, child, end, note}`）：不另外登記，在「請假登記」選這些假別時跳出視窗詢問事件日期並建立（喪假若已有可對應的喪事，會先問「這次是為了哪一件事」，可選既有的或「新的事件」另填死亡日與親屬關係）。婚假、喪假、產檢假的請假紀錄帶 `pevId` 指向所屬事件，已請天數依事件計算（舊資料沒有 `pevId` 時依可請期間判斷）；已核准＋待審核＋這次超過該事件可請天數時，助理本人無法送出，管理者要確認才能登記；個人假統計的「事件假統計」只列出統計（可刪除事件）。婚假 14 日（結婚登記日前 10 日起、3 個月內請畢；3 個月後至 1 年內登記時跳出「需經公司同意」提醒，審核表格也會標示）、喪假 8／6／3 日（死亡後 100 天內）、產檢假 7 日（生產前）；產假 56 日、流產產假 56 日／4 週／1 週／5 日、育嬰假（以月為單位、最短 6 個月，填起始日與月數；應於 10 日前提出，助理本人來不及時無法送出、管理者登記時提醒；每名子女在滿 3 歲前合計最長 2 年〔含彈性育嬰假〕，可分次請、期間不能重疊；全部撤回或取消的育嬰假不算重疊也不算天數，撤回全部時事件一併刪除）為連續假，登記時填起始日與結束日（產假、流產產假預設請滿，可改短），自動把起訖期間（含假日）排入全天請假（`leaves.eventId` 指回事件，刪除事件時一併刪除）。

**病假**：每診扣出勤津貼的 1/4（比例可調整），最多扣到 0；病假本身的請假扣款另計。

**事假補診**：不需登記。以當月排班表中的「加診」診數當作補診（`makeupShifts`＝`monthCounts` 的 `extra`）；當月加診診數少於事假診數時，當月不發出勤津貼。「助理請假」分頁的事假補診統計卡片列出每位助理的事假、加診與出勤津貼狀態，可用「◀ 月｜年 ▶」切換月份或整年（整年時逐月列出）。不影響事假的請假扣款。舊的 `makeups` 紀錄不再使用。

實發 = 應發 − 扣除 + 加減項，**無條件進位到十位數**（例如 5,401 → 5,410）；薪資表與匯出另有「實發（未進位）」欄顯示進位前金額。每分鐘金額、每則金額與三項津貼的預設值等薪資計算規則可依月份不同：在「薪資」分頁最上方選擇年月後修改，存到 `config/main.payByMonth[YYYY-MM]`，從該月起生效，之後沒有另外修改的月份沿用（更早的月份用舊版共用的 `config/main.pay`）。薪資表與薪資計算規則都依最上方選擇的年月。頁面上方的「上個月／本月／下個月」只在排班表分頁顯示。

## 排休抽籤

「排休抽籤」分頁（管理者與助理可見，僅檢視的助理也能參加）。以月為單位，每個月的抽籤遊戲預設是關閉的。

- **本月抽籤預設**（還沒設定名額的月份，分頁最下方，管理者）：抽籤日期（前一個月幾號）、時間、自動進入下一輪要等幾分鐘、每人籌碼、每天名額，存在 `config/main.lotByMonth[YYYY-MM]`；沒有調整的月份自動沿用前一個（最近一次調整的）月份，都沒有時用系統預設（前一個月 10 號 22:00、10 分鐘、4 枚、2 名額）。

- **開啟抽籤遊戲**：管理者按「設定 YYYY年 M月 名額」→ 在月曆上直接填入每天的名額（填 0 ＝不開放）（週日與診所休診日預設 0），並設定這個月的籌碼數、抽籤日期與時間、自動進入下一輪要等幾分鐘、參加人員（預設在職助理，不含教育中）→ 按「開啟抽籤遊戲」後助理才看得到、才能放籌碼。第 1 輪開獎前可按「關閉抽籤遊戲」回到未開啟狀態修改（已放的籌碼保留）。
- **放籌碼**：助理在月曆上點日子放籌碼（一天一枚），再點一次收回，可一直改到截止。每天顯示剩餘名額與目前想要的人數。
- **大家的籌碼**：狀態列下方列出每位參加者的籌碼（已放／未放）與是否已「下好離手」，所有人都看得到。
- **下好離手**：放好後按「下好離手」（還有沒放的籌碼會先確認，下好離手後視為放棄），要修改先按「取消」。所有還有籌碼的人都下好離手就提前截止（本輪截止改成現在，`earlyAt` 記錄時間）；否則等時間到（第 1 輪為抽籤時間，之後每輪預設 10 分鐘）。
- **開獎倒數**：抽籤時間到（或全部下好離手）就截止放籌碼，畫面正中間大字倒數 5、4、3、2、1，倒數完開獎並播放開獎動畫。
- **開獎**：時間到，想要同一天的人超過名額就抽籤（名字輪流亮起後停在抽中的人），沒抽中的籌碼退回，立刻進行下一輪：在時限內放到還有名額、自己還沒抽中的日子，時限內沒放的籌碼視為放棄；直到沒人有籌碼或沒有名額。
- **本月原始排班醫師班表**（排班管理以上）：抽籤月曆每天下方直接列出早／午／晚有哪些醫師（依代號 A–Z 由左到右、同一人上下對齊）（已定案用原始班表 `baselines`，還沒定案用目前的班表），方便決定每天名額。不存進抽籤資料，助理在抽籤頁看不到醫師班表。
- **公平可驗證**：每輪的亂數種子＝SHA-256（月份、輪次、開獎時間、所有人的籌碼），任何人觸發開獎結果都一樣；「驗證結果」按鈕會從頭重算每一輪並比對。
- **確認登記**：抽籤完成後，管理者按「確認登記排休」，把抽中的日子登記為「排休」（事前、全天，備註「排休抽籤」）；已經有請假紀錄的日子略過。
- **限制**：系統沒有後端伺服器，開獎需要至少一位管理者或參加的助理在時間到時開著這個分頁（或之後第一個打開系統的人觸發，後續輪次從那時起算）。
- 資料：`lottery/{YYYY-MM}`（設定、目前輪次 `round`、本輪截止 `roundEndsAt`、每輪紀錄 `rounds`、抽中結果 `won`、退回的籌碼 `left`）、`lotteryBets/{YYYY-MM}_{輪次}_{staffId}`（`{ym, round, sid, dates, ready, at}`）。規則：籌碼只能放自己的且要在本輪截止前；開獎結果只有管理者或參加者在截止後能寫入；參加者只能把本輪截止提前到現在附近（下好離手提前開獎用）。

## 出勤打卡（臉部辨識）

| 部分 | 檔案 | 說明 |
|---|---|---|
| 打卡頁 | `kiosk.html` | 放在診所平板上的打卡機。用 [Human](https://github.com/vladmandic/human) 在裝置上做臉部偵測、特徵比對與活體／防翻拍檢查（相片、螢幕翻拍會被擋），只把打卡時間寫到 Firestore |
| 出勤分頁 | `index.html` 的「出勤」 | 排班管理以上可見。比對打卡與班表、補登／作廢打卡、把遲到分鐘帶入薪資、出勤規則、核准打卡裝置、設定裝置管理密碼 |
| App | `kiosk-app/` | Expo（React Native）外殼，用 WebView 開啟正式網址的 `kiosk.html`；處理相機權限、全螢幕、螢幕常亮、斷線自動重試 |

**流程**：平板開 App → 第一次開啟會匿名登入並顯示「裝置代碼」→ 管理者在「出勤 → 打卡裝置」核准 → 設定裝置管理密碼 → 在平板右上角 ⚙ 輸入密碼 →「登錄臉部」逐一為人員登錄（本人勾選同意，擷取 5 個角度）→ 之後打卡時先點選「班別＋上班卡／下班卡」（6 個按鈕，依現在時間建議最可能的一個），再站到鏡頭前掃臉；辨識成功後顯示姓名與遲到／早退提示，2.5 秒內可按「不是我」取消。選的班別當天沒有排班時會警告，需要本人按「確認打卡」。30 秒內沒辨識到或打完卡會回到選擇畫面。

**打卡規則**：每一診都要打上班卡與下班卡（早班連午班也要在中午打下班、再打上班）。打卡時選的班別存在 `punches.sel`，直接算在那一診（同一個時間點有多筆時上班取最早、下班取最晚；選了沒排的診列為「其他」）。沒有 `sel` 的打卡（舊紀錄、補登時選「依時間自動判斷」）才依時間順序對應到還空著的時間點（動態規劃：先求對上最多、再求時間差總和最小；差 180 分鐘以上不對應）。
- 遲到：上班卡晚於開診超過「遲到寬限」→ 從開診時間起算的分鐘數；早退：下班卡早於結束超過「早退寬限」。晚班在「晚班可下班時間」（`nightOut`，預設 21:00）之後打下班卡不算早退，早於這個時間時早退分鐘也從這個時間起算。
- 應出勤＝到今天為止、已結束、沒有請假的診次（依 `weeks`，也就是定案後的異動班表）。出勤率＝上下班卡都有的診數 ÷ 應出勤。
- **臨時加班**：打卡端選擇畫面最下方的「臨時加班 上班卡／下班卡」隨時可打，不受班表與可打卡時段限制（`sel.sh='extra'`），不列入出勤率、遲到、早退、缺卡。臨時加班下班卡一律成為加班申請（`ot.extra=true`），分鐘數從當天最近一張臨時加班上班卡起算（`ot.from`），必須有原因：臨時加班上班卡可以先填原因（存在 `extraReason`，也可「稍後再填」）；下班卡會帶出上班時填的原因，可「沿用並送出」或「修改原因」，上班時沒填就必須填（沒有「不用」選項）。60 秒沒動作：有上班原因就沿用，沒有則送出並標示「未填寫原因」；找不到上班卡時分鐘數顯示「?」，由主管核准時填入。
- **審核醫師**：申請加班（一般加班與臨時加班下班卡）時必須選一位在職醫師審核（`ot.reviewer`＝醫師的 staffId），預設為這一診跟診配對的醫師（班表 `L` 欄）。只有被指定的審核醫師或超級管理員可以核准／退回（安全規則：審核醫師只能改 `ot`、不能換審核醫師；排班管理可以補登、作廢但不能動 `ot`）。醫師登入後在「加班審核」分頁看到指定給自己的申請；超級管理員看到所有月份的待審申請。醫師需要在人員名單綁定登入帳號（「僅檢視」即可）；未指定審核醫師的申請只有超級管理員能審。
- **曠職**：「曠職起算日」（`absentFrom`，出勤規則；空白＝不計曠職）之後，有排班、該診已結束、上下班卡都沒打、沒有請假也沒有家庭照顧假的診算曠職；補登打卡或補請假後自動不再算曠職（都是即時計算）。只缺上班卡或只缺下班卡的列為「未打卡（待確認）」。薪資「曠職扣款」＝曠職診數 × 每診設定薪資 × 曠職扣薪比例（`absentRate`，預設 1）；「有曠職不發出勤津貼」（`absentNoAttend`，1＝是）。薪資頁與匯出會先載入當月打卡再計算。
- **撤銷核准**：已核准的加班，超級管理員或該筆的審核醫師可以在核准後 `revokeDays`（出勤規則可調，預設 3 天，0＝不限制）天內按「撤銷核准」（超過期限按鈕改為「已超過撤銷期限」），選「改回待審」或「改為退回」並填撤銷原因；撤銷紀錄存在 `ot.revoked:{prevMin,prevByName,byName,at,note}`，狀態欄顯示「曾由 xxx 核准 N 分，yyy 撤銷：原因」。若這筆核准當初取代了前一筆申請，前一筆不會自動恢復；已帶入薪資的需重新帶入。
- **管理者新增加班**：「出勤 → 加班申請」的「＋ 新增加班」（排班管理以上）：選人員、日期、班別、下班時間（臨時加班另填開始時間），加班分鐘依該診結束時間（或臨時加班開始時間）自動算出、可修改；原因必填。建立一筆補登的下班卡（`src:'manual'`）附上 `ot.manual:true`、`ot.addedBy`。排班管理新增的必須指定審核醫師、狀態為待審；超級管理員可勾「直接核准」。同一天同一班已有加班時會提醒。安全規則：只有超級管理員能直接建立已核准的加班。
- **同一班重複申請加班**：同一天同一班（含臨時加班）已有加班申請時，打卡裝置送出前詢問。前一筆待審：「改用這一筆」把前一筆標成 `status:'replaced'`（記 `replacedBy`，新申請記 `ot.replaces`），「保留前一筆」則這次只打下班卡；前一筆已核准／退回：詢問是否「另外申請」；前一筆已核准而另外申請時，新申請記 `ot.prev:{id,min,ts}`，審核醫師只能「核准並取代前一筆」（前一筆改為 replaced，記 `replacedBy`、`replacedByName`）或「退回」，不能兩筆都保留。安全規則允許新申請的審核醫師把它 `ot.prev` 指向的已核准申請改成 replaced。已被取代的申請不審核、不計入加班分鐘。安全規則只允許打卡裝置把待審改成 replaced。
- **接續下一診**：下班卡時間已超過當天下一診（有排班）的開始時間時，加班最多算到兩診中間的間隔，並同時自動打下一診的上班卡（`auto:true`，`link` 指回下班卡；下班卡記 `next`）。這張接續上班卡照算遲到，但下班卡的加班**核准後下一診不算遲到**（待審時標示「前一診加班審核中」）。即使沒到下一診開始，只要有排下一診，加班也最多算到兩診中間。
- **打卡裝置雙軌核准**：裝置代碼是匿名登入帳號 ID 的前 6 碼，清除資料、重裝 App、換瀏覽器都會變。App 會把系統的裝置編號交給網頁（`window.KIOSK_HW`），核准時可選「綁定裝置編號」（之後代碼變了也自動沿用）或「只核准這個代碼」；用瀏覽器開啟的沒有裝置編號，只能以代碼核准。`isKiosk()`：`devices/{uid}.approved` 或其 `hwId` 對應的 `hw/{id}.approved` 任一成立。
- **打卡端查看紀錄**：右上角「打卡紀錄」按鈕，不需密碼、人人可看。可切換單日／整月、上一個／下一個、今天，並依人員篩選；每筆顯示時間、姓名、哪一診上班／下班（接續、臨時加班、補登）、遲到／早退（依該週班表）與加班申請狀態。不顯示照片、不列出已作廢的打卡；60 秒沒操作自動關閉。
- **防重複打卡**：同一人同一班的同一種卡（例如都是早診上班卡），`dupMin`（預設 5）分鐘內不能重複打，會提示上次打卡時間並回到選擇畫面；填 0 不限制。
- **可打卡時段**：上班卡在開診前 `inBefore`（預設 60）～開診後 `inAfter`（預設 180）分鐘；下班卡在結束前 `outBefore`（預設 180）～結束後 `outAfter`（預設 180）分鐘。時段外的按鈕在打卡裝置上呈灰色無法選擇（每 30 秒更新），可在出勤規則調整。
- **加班申請**：下班卡比該診結束時間（晚班 21:30）晚超過「下班超過幾分鐘詢問加班」（`otAsk`，預設 3 分鐘，0＝不詢問），打卡裝置會詢問是否申請加班，申請必須填原因（可點選常用原因再補充）；不申請或 60 秒沒回應就只打下班卡。申請存在該筆打卡的 `ot`（裝置只能送出 `status:'pending'`），管理者在「出勤 → 加班申請」核准（可調整分鐘數）或退回。
- 「帶入薪資（遲到、早退、加班）」：遲到、早退分別寫入 `pay/{staffId}_{YYYY-MM}.lateMin`、`earlyMin`；當月**已核准**的加班分鐘合計寫入 `otMin`（取代原本手動填的加班/拖診分鐘數）。帶入前會列出變更讓管理者確認。

**Firestore**（規則見 `firestore.rules`）：

| 路徑 | 內容 |
|---|---|
| `devices/{匿名uid}` | `{name, approved, at, ua, hwId?, model?}`；裝置自己建立（approved 必須是 false，只能自己補上 hwId／model），排班管理以上核准 |
| `hw/{裝置編號}` | `{approved, name, model, platform, at}`：App 回報的裝置編號（Android ID 或 iOS identifierForVendor，前綴 `and-`／`ios-`），核准後同一台平板換了代碼也能打卡 |
| `punches/{id}` | `{staffId, ts, date, src:'kiosk'\|'manual', sel:{sh,k}?, ot:{min,reason,reviewer?,replaces?,revoked?,status:'pending'|'approved'|'rejected'|'replaced',approvedMin?,by?,note?}?, device, devName, sim, real, live, photo?, by?, note?, void?}`（`sel`：打卡時選的班別與上班 in／下班 out）。裝置只能新增；補登、作廢（`void`，保留紀錄）由管理者處理 |
| `faces/{staffId}` | `{emb: JSON 字串（5 組特徵值）, n, at, consentAt, device}`，不存照片 |
| `kiosk/rules` | `kiosk/settings` 去掉 `pinHash` 的副本（排班管理儲存規則時同步寫入），所有已開通的帳號可讀，讓僅檢視的人用同樣規則計算自己的出勤 |
| `kiosk/settings` | `{graceIn, graceOut, nightOut, absentFrom, otAsk, dupMin, revokeDays, inBefore, inAfter, outBefore, outAfter, photo, thr, pinHash}` 出勤規則、辨識門檻、裝置管理密碼（SHA-256） |

**第一次上線要做的事**
1. Firebase 主控台 → Authentication → 登入方式 → 啟用「匿名」。
2. 把新版 `firestore.rules` 貼到 Firebase 主控台發布。
3. 推上 `main`（Vercel 會部署 `kiosk.html`）。

**個資**：臉部特徵值屬於生物特徵個資，登錄時需本人勾選同意；離職時到「出勤 → 人員明細 → 刪除臉部資料」刪除。打卡小照片（112×112）可在出勤規則關閉。

**建置 App**（需要 Node.js LTS 與免費的 [Expo](https://expo.dev) 帳號；iOS 另需 Apple Developer Program）：
```
cd kiosk-app
npm install
npx expo install --fix
npx eas-cli login
npx eas-cli build -p android --profile preview   # 產出 APK，直接安裝到 Android 平板
npx eas-cli build -p ios --profile preview       # 需 Apple Developer 帳號，先用 eas device:create 登記 iPad
```
平板建議開「螢幕固定」（Android）／「引導使用模式」（iPad），避免被切到其他 App。

**下載頁**：`app.html`（正式網址 `/app.html`，排班系統「出勤 → 打卡裝置」右上角也有連結）提供最新版 APK 的下載按鈕、QR code（指向下載頁本身，換版本不用重印）、版本與安裝步驟，內容讀 `app-latest.json`。每次建置完成後，在 `kiosk-app` 執行 `node set-latest.js "這一版的更新說明"` 更新 `app-latest.json`，再 commit／push。`eas.json` 的 preview 設定 `autoIncrement`，每次建置版本號（第 N 版）自動加 1。

**本機測試**：`index.html?local=名稱` 與 `kiosk.html?local=名稱` 共用 localStorage（打卡資料存在 `clinic_kiosk_local_v1_名稱`）；沒有相機時可在主控台用 `__kiosk.simulate('人員id')` 模擬辨識成功。

## 本機使用

本機模式可以在網址加上 `&as=權限:人員id`（例如 `index.html?local=test&as=view:a1`）模擬某個帳號登入後看到的畫面，只在 localhost 有效。

直接用瀏覽器打開 `index.html` 就可以使用。如果要開 GitHub Pages：repo 的 Settings → Pages → Branch 選 `main`，路徑選 `/ (root)`。
